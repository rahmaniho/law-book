### ۱.۲. معماری واقعی: «تماماً کلاینت، بدون سرور»

```
data/sources/**  (متون خام: CSV, TXT, JSON, YAML)
        │
        ▼  scripts/build-data.mjs  +  build-cases.mjs   (زمان بیلد، Node)
        │
public/data/
   version.json                      ← اشاره‌گر نسخه + هشِ هر قانون
   v/1.0.0+65fd6099/
       catalog.json                  ← فهرست، دسته‌ها، سلسله‌مراتب، اعتبارنامه
       laws/<lawId>.p<n>.json        ← قطعه‌های ~۳۰۰ ماده‌ای
       cases/index.json + c0..c9     ← آراء قضایی (دریافت اختیاری)
        │
        ▼  استقرار ایستا روی GitHub Pages (basePath = /Lawbook)
        │
   ┌────┴────────────────────────────────────────────────┐
   │  مرورگر کاربر                                        │
   │   DataBootstrap → syncData() → همگام‌سازی دلتا بر    │
   │   پایهٔ هش → Dexie/IndexedDB                        │
   │   Service Worker: کش پوسته + کش دائمی دادهٔ نسخه‌دار  │
   │   Web Worker: ایندکس MiniSearch                     │
   └─────────────────────────────────────────────────────┘
```

**نکتهٔ کلیدی معماری:** کل محصول یک وب‌اپلیکیشن ایستاست که داده‌هایش را از فایل‌های JSON
عمومی می‌گیرد و در IndexedDB نگه می‌دارد. هیچ سرور، هیچ API، هیچ حساب کاربری و هیچ پایگاه‌دادهٔ
مرکزی در کار نیست.

### ۱.۳. نقطهٔ ورود و زنجیرهٔ راه‌اندازی

`src/app/layout.tsx` → `ThemeProvider` → `DataBootstrap` → `AppShell` → صفحه
و به‌صورت موازی `ServiceWorkerRegistrar`.

`DataBootstrap` تا وقتی `ready` نشده، اسپلش با نوار پیشرفت نشان می‌دهد؛ اول کاتالوگ کش‌شده را
می‌خواند (اجرای فوری آفلاین)، بعد `syncData()` را صدا می‌زند.

### ۱.۴. مسیریابی

مسیریابی فایل‌محور App Router با `trailingSlash: true`. مسیرهای موجود:

```
/                          /laws                 /laws/[lawId]        (۴۶ مسیر)
/article/[articleId]       (۷٬۲۷۸ مسیر!)          /search              /bookmarks
/cases                     /settings             /coverage            /about
/calculator/inheritance    /calculator/diyyeh    /offline             /not-found
```

`generateStaticParams` هر ۷٬۲۷۸ ماده را به‌صورت یک صفحهٔ HTML جداگانه پیش‌رندر می‌کند.
**این تصمیم طراحی در بخش ۸ و ۹ پیامدهای مهمی دارد.**

### ۱.۵. مدیریت `basePath` — نقطهٔ قوت معماری

فایل `config/base-path.mjs` تنها مرجع `basePath` است و `next.config.mjs`،
`scripts/build-manifest.mjs`، `src/lib/base-path.ts` و `public/sw.js` همگی از آن تغذیه می‌شوند.
مقدار پیش‌فرض `/Lawbook`. این لایه عمداً ساخته شده چون Next.js فیلدهای `metadata.manifest` و
`metadata.icons` را با basePath ترکیب نمی‌کند — بدون آن دکمهٔ «نصب» PWA هرگز فعال نمی‌شد.
آزمون‌های این مسیر در `tests/pwa.test.mjs` واقعاً سرویس‌ورکر را در یک `vm` context جدا اجرا می‌کنند.
**این کار درست انجام شده و نباید دست بخورد.**

### ۱.۶. ذخیره‌سازی محلی (`src/lib/db.ts`)

پایگاه‌داده `GhanounDB` با Dexie، نسخهٔ اسکیمای ۲:

| جدول | ایندکس‌ها | نقش |
| --- | --- | --- |
| `laws` | `id, category, hierarchy, approvalSort` | فراداده + **هش** هر قانون |
| `articles` | `id, lawId, numberValue, category, hierarchy, status, *keywords` | متن مواد |
| `bookmarks` | `articleId, lawId, createdAt` | نشان‌ها |
| `notes` | `articleId, lawId, updatedAt` | یادداشت شخصی |
| `history` | `++id, q, createdAt` | تاریخچهٔ جست‌وجو (سقف ۶۰ ردیف) |
| `meta` | `key` | کاتالوگ، نسخهٔ داده، تنظیمات، زمان آخرین sync |
| `cases` | `id, type, dateSort` | آراء قضایی (اختیاری) |
| `caseIndex` | `id, type, dateSort` | فهرست سبک آراء برای جست‌وجو |

### ۱.۷. همگام‌سازی دلتا (`src/lib/sync.ts`) — نقطهٔ قوت مهم

`version.json` با `cache: 'no-store'` خوانده می‌شود؛ برای هر قانون `hash` ذخیره‌شده با
`hash` اشاره‌گر مقایسه می‌شود و **فقط قوانین تغییرکرده** دوباره دانلود می‌شوند. دانلود
قطعه‌قطعه با گزارش پیشرفت بایت‌به‌بایت از طریق `ReadableStream` انجام می‌شود.

### ۱.۸. ماژول آراء قضایی (`src/lib/cases.ts`) — **مهم‌ترین یافتهٔ تجاری**

این ماژول دقیقاً الگوی «بستهٔ اختیاری قابل دانلود» را پیاده کرده است:

```ts
interface CasesStatus {
  available: boolean;   // آیا در این نسخهٔ داده وجود دارد؟
  enabled: boolean;     // آیا کاربر فعالش کرده؟
  downloaded: boolean;  // آیا روی این دستگاه نصب شده؟
  count, bytes, types, version
}
downloadCases(onProgress, signal)   // دانلود با پیشرفت و قابلیت لغو
disableCases()                      // حذف از دستگاه
```

**نتیجه‌گیری:** سیستم «بستهٔ به‌روزرسانی پولی» نیازی به طراحی از صفر ندارد. ماژول `cases.ts`
۷۰٪ منطق موردنیاز (وضعیت موجود/فعال/دانلودشده، پیشرفت، لغو، دانلود مجدد، حذف) را دارد و فقط باید
با یک لایهٔ **مجوز** و **اعتبارسنجی هش** تقویت شود. این یک صرفه‌جویی جدی در هزینهٔ توسعه است.

### ۱.۹. Service Worker (`public/sw.js`, نسخهٔ `v2`)

| منبع | راهبرد |
| --- | --- |
| ۸ مسیر پوستهٔ اصلی (`/`, `/laws/`, `/search/`, `/bookmarks/`, `/settings/`, `/about/`, `/offline/`, `/coverage/`) | پیش‌کش در `install` |
| `/data/v/<version>/…` | **cache-first** (تغییرناپذیر) |
| `/data/version.json` | network-first با پشتیبان کش |
| `/_next/static/`, `/icons/`, `/fonts/` | cache-first |
| ناوبری (`mode === 'navigate'`) | network-first → کش → صفحهٔ `/offline` |
| `sync` / `periodicsync` | بررسی نسخهٔ جدید داده و `postMessage` به برنامه |

### ۱.۱۰. هویت بصری فعلی (بررسی‌شده — مهم برای بخش ۱۲ سند شما)

**هویت فعلی سرمه‌ای نیست.** رنگ برند فیروزه‌ای/سبزآبی (teal) است:

```
brand-500 #14b8a6   brand-600 #0d9488   brand-700 #0f766e   brand-900 #134e4a
theme_color در manifest: #0f766e        دارک‌مود: #042f2e
رنگ مکمل: sand-50/100/200 (#fdfbf7 … #efe4ce)
```

> **توصیه:** فیروزه‌ای را به‌عنوان رنگ اصلی حفظ کنید (در manifest، آیکون‌ها، splash و کل UI
> تثبیت شده و تغییرش یعنی بازسازی آیکون‌ها و از دست دادن شناسایی برند). سرمه‌ای را به‌عنوان
> رنگ **ثانویه و مخصوص بخش تجاری** (فروشگاه، حساب کاربری، فاکتور) اضافه کنید. این کار «طراحی
> یکپارچه با هویت کارن سافت» را بدون بازطراحی پرهزینه و پرریسک محقق می‌کند.

### ✅ چیزی که واقعاً آفلاین کار می‌کند

- کل متن ۴۶ قانون / ۷٬۲۷۸ ماده در IndexedDB است.
- ایندکس جست‌وجو محلی ساخته می‌شود؛ جست‌وجو بدون اینترنت کار می‌کند.
- ۸ مسیر پوستهٔ اصلی پیش‌کش می‌شوند.
- فونت‌ها، آیکون‌ها و تمام دارایی‌ها محلی‌اند؛ **هیچ درخواست شبکه‌ای به دامنهٔ خارجی وجود ندارد**.
- محاسبه‌گرهای ارث و دیه کاملاً محلی‌اند.
- نشان‌ها، یادداشت‌ها و تاریخچه محلی‌اند.

### ❌ شکاف تأییدشده

سند شما در بند ۵.۱ می‌گوید: «نصب PWA یا ذخیرهٔ صفحهٔ اصلی به‌تنهایی به معنی آفلاین‌شدن تمام
امکانات نیست.» دقیقاً همین اتفاق اینجا افتاده است.

Next.js در حالت export برای **ناوبری سمت کلاینت** یک فایل RSC payload به نام `index.txt`
کنار هر صفحه می‌سازد (۷٬۳۳۵ فایل در این بیلد). Service Worker این فایل‌ها را رهگیری نمی‌کند:
آن‌ها نه زیر `/_next/` هستند، نه `mode === 'navigate'`، نه زیر `/data/v/`.

**روش تأیید:** منطق واقعی `public/sw.js` در یک `vm` context ایزوله اجرا شد (همان روشی که
آزمون‌های خود پروژه استفاده می‌کنند) و رویداد `fetch` برای URLهای واقعی شبیه‌سازی شد:

```
✅ رهگیری می‌شود  | پوستهٔ پیش‌کش‌شده (navigate)              /Lawbook/laws/
✅ رهگیری می‌شود  | صفحهٔ ماده (navigate / reload)            /Lawbook/article/civil-code-10/
❌ رهگیری نمی‌شود | RSC payload صفحهٔ ماده                    /Lawbook/article/civil-code-10/index.txt
❌ رهگیری نمی‌شود | RSC payload صفحهٔ قانون                   /Lawbook/laws/civil-code/index.txt
✅ رهگیری می‌شود  | دادهٔ نسخه‌دار قانون                       /Lawbook/data/v/…/civil-code.p0.json
✅ رهگیری می‌شود  | اشاره‌گر نسخه                             /Lawbook/data/version.json
✅ رهگیری می‌شود  | چانک استاتیک                              /Lawbook/_next/static/chunks/main.js
```

**پیامد:** کاربر آفلاین که روی کارت یک ماده کلیک می‌کند، درخواست `index.txt` شکست می‌خورد؛
Next به ناوبری سخت (hard navigation) برمی‌گردد؛ آن ناوبری به `networkFirstNavigation` می‌رسد؛
شبکه نیست؛ کش پوسته فقط ۸ مسیر دارد و این مسیر در آن نیست؛ **نتیجه: صفحهٔ «آفلاین» نمایش
داده می‌شود** — در حالی که متن همان ماده همان لحظه در IndexedDB موجود است.

> **محدودیت این یافته (صادقانه):** این نتیجه از اجرای قطعی منطق SW به‌دست آمده، نه از یک تست
> مرورگر واقعی با شبکهٔ قطع. رفتار دقیق fallback روتر Next ممکن است در نسخه‌های مختلف فرق کند.
> **اولین کار فاز دوم باید یک تست واقعی روی اندروید/کروم با حالت آفلاین باشد.**

### راه‌حل پیشنهادی (دو گزینه، هر دو ارزان)

1. **کم‌هزینه و فوری (~۰٫۵ روز):** یک قاعده به SW اضافه شود که `*.txt` هم‌مبدأ را با
   stale-while-revalidate کش کند، به‌علاوه پیش‌کش کردن ۴۶ مسیر `/laws/<id>/`.
2. **راه‌حل اصولی و هم‌راستا با تجاری‌سازی (~۲ روز):** مسیرهای `/article/[articleId]` از
   پیش‌رندر خارج شوند و به یک مسیر کلاینتی واحد تبدیل شوند. نتیجه: بیلد از ۷٬۳۳۸ صفحه به
   حدود ۱۲ صفحه و از ۲۰۶ مگابایت به چند مگابایت می‌رسد، شکاف آفلاین کاملاً بسته می‌شود، **و
   محتوای پولی دیگر توسط گوگل ایندکس نمی‌شود** — که برای یک محصول فروشی یک مزیت است، نه ضرر.
   هزینه: از دست رفتن SEO دیپ‌لینک مواد، که با یک سایت معرفی/فروش جداگانه جبران می‌شود.

**توصیهٔ من: گزینهٔ ۲.** یک تغییر، سه مشکل را هم‌زمان حل می‌کند.

### طراحی مجوز مادام‌العمر که واقعاً مادام‌العمر است

این دقیقاً همان نکته‌ای است که سند شما بر آن تأکید دارد و اغلب اشتباه پیاده می‌شود:

```
۱) پرداخت موفق → سرور مستقیماً از API رسمی درگاه verify می‌کند (نه از بازگشت مرورگر)
۲) سرور یک «گواهی مجوز» صادر می‌کند:
   {
     licenseId, userId, product: "lawbook",
     edition: "base", purchasedVersion: "1.0.0",
     packages: ["pkg-1404-01", ...],
     deviceId, issuedAt,
     perpetual: true          ← بدون exp
   }
   امضا: Ed25519 با کلید خصوصیِ فقط-سرور
۳) PWA گواهی را در IndexedDB نگه می‌دارد و **آفلاین** با کلید عمومیِ
   تعبیه‌شده در باندل، امضا را بررسی می‌کند.
۴) برنامه آفلاین هیچ‌گاه گواهی را باطل نمی‌کند. هرگز.
۵) بررسی ابطال (تراکنش برگشتی، تقلب) فقط وقتی آنلاین است و
   **فقط** پاسخ قطعی و امضاشدهٔ سرور می‌تواند وضعیت را تغییر دهد.
۶) پاک‌شدن حافظهٔ مرورگر = ورود دوباره به حساب و صدور مجدد همان گواهی.
```

نتیجه: انقضای سشن، قطع اینترنت، یا نخریدن به‌روزرسانی **هیچ‌کدام** حق استفاده از نسخهٔ
خریداری‌شده را از بین نمی‌برند — دقیقاً مطابق بندهای ۳.۱ و ۷ سند شما.

### محدودیت دستگاه — واقعیت مرورگر (صادقانه)

مرورگر **شناسهٔ پایدار دستگاه ندارد**. هر چه بسازیم یک شناسهٔ تصادفی در IndexedDB است که با
پاک‌کردن داده‌های مرورگر از بین می‌رود. بنابراین:

- شناسهٔ دستگاه = UUID تصادفی، ساخته‌شده هنگام فعال‌سازی، ثبت‌شده روی سرور.
- سقف دستگاه از پنل مدیریت تنظیم شود (پیشنهاد اولیه: ۳) و **قبل از خرید** به کاربر اعلام شود.
- کاربر بتواند خودش دستگاه قبلی را حذف کند.
- پاک‌شدن حافظه → دستگاه جدید محسوب می‌شود → کاربر باید بتواند خودش آزاد کند، وگرنه پشتیبانی
  به گلوگاه تبدیل می‌شود.
- اثرانگشت مرورگر (fingerprinting) **توصیه نمی‌شود**: غیرقابل‌اتکا، مزاحم و از نظر حریم خصوصی بد.

> ⚠️ **هیچ راهکار سمت کاربر محافظت صددرصدی نیست.** کاربری که محتوا را آفلاین دارد، می‌تواند
> آن را استخراج کند. هدف واقعی: کپی‌برداری را به‌قدری پرزحمت کنیم که خرید ساده‌تر باشد، و
> ارزش را به **به‌روزرسانی مستمر** گره بزنیم — چیزی که کپی‌کننده نمی‌تواند تکثیر کند. این
> استدلال باید مبنای مدل درآمدی باشد، نه DRM.

## ۱۱. مدل دادهٔ پیشنهادی (پیش‌نویس فاز دوم)

```
Users            id, phone(unique), displayName?, status, createdAt, lastLoginAt
Products         id, slug, title, description, status
ProductVersions  id, productId, version, releasedAt, changelog, status
Prices           id, productId|packageId, amountRial, currency, activeFrom, activeTo

                 status(active|suspended|revoked), perpetual, maxDevices, issuedAt

Orders           id, userId, items[], amountSnapshot, status, idempotencyKey(unique), createdAt
Payments         id, orderId, gateway, gatewayAuthority, gatewayRefId,
                 amount, status, verifiedAt, rawResponse
UpdatePackages   id, version, title, releasedAt, legalCoverageDate, changelog,
                 newLaws[], amendedLaws[], repealedLaws[], sizeBytes,
                 fileKey, sha256, priceId, status(draft|published|halted)
UpdatePurchases  id, userId, packageId, orderId, grantedAt      UNIQUE(userId, packageId)
UserDevices      id, userId, deviceId, label, userAgentHash, firstSeenAt, lastSeenAt, revokedAt
DownloadRecords  id, userId, packageId, deviceId, bytes, status, createdAt
```

**قواعد الزامی:**
- `Orders.amountSnapshot` قیمت را در لحظهٔ ایجاد سفارش **قفل** می‌کند؛ تغییر قیمت بعدی بی‌اثر است.
- صدور مجوز **فقط** پس از `Payments.status = verified` توسط API رسمی درگاه.
- `UNIQUE(userId, packageId)` پرداخت مجدد برای بستهٔ یکسان را در سطح پایگاه داده غیرممکن می‌کند.
- هیچ رکورد مالی **هرگز حذف فیزیکی نمی‌شود** — فقط وضعیت تغییر می‌کند و در `AuditLogs` ثبت می‌شود.

### پرسش ۱ — کد تجاری کجا نوشته شود؟

محتوا در حال حاضر رایگان و عمومی است.
الف) **فریمیوم (توصیهٔ من):** یک زیرمجموعهٔ رایگان (مثلاً قانون اساسی + مدنی) عمومی بماند؛ کل مجموعه + آراء + محاسبه‌گرها پشت مجوز بروند

ج) **فقط به‌روزرسانی‌ها پولی:** نسخهٔ فعلی رایگان بماند و فقط بسته‌های آینده فروخته شوند (کم‌ریسک‌ترین از نظر اعتماد کاربر، ولی درآمد اولیه ندارد)

### پرسش ۳ — زیرساخت
الف) یک VPS ایرانی (~۲٫۱ میلیون تومان ماهانه) — توصیهٔ من
ب) PaaS (~۲٫۵–۳ میلیون، عملیات کمتر)
ج) سرور یا هاستی از قبل دارید

### پرسش ۴ — وضعیت پذیرندگی
آیا **اینماد**، **کد رهگیری مالیاتی** و **حساب درگاه پرداخت** را دارید؟

## ۱۴. جمع‌بندی

کاربری، مجوز، پرداخت و پنل مدیریت — که هیچ‌کدام وجود ندارند و همگی افزودنی‌اند.

هر دو از امروز قابل شروع‌اند — به‌موازات توسعه.
