# کتابچه قانون ایران — law-book

مونوریپوی تجاری‌سازی **Lawbook**، برند **KarenSoft | کارن سافت**.
مدل تجاری: خرید یک‌بارهٔ نسخه با مجوز مادام‌العمر + به‌روزرسانی‌های پولی اختیاری؛ نه اشتراک اجباری.

## ساختار

| مسیر | وضعیت |
| --- | --- |
| `apps/web` | PWA موجود؛ واردشده از `rahmaniho/Lawbook`، با اصلاح مسیرهای مطالعهٔ آفلاین |
| `apps/api` | اسکلت Fastify/TypeScript؛ فقط sandbox، پرداخت و صدور مجوز **هنوز پیاده‌سازی نشده** |
| `apps/admin` | محل رزروشده و مستند؛ پنل هنوز ساخته نشده است |
| `docs` | گزارش ممیزی، منشأ سورس و گزارش پیشرفت |
| `tools` | آزمون SW، آزمون واقعی مرورگر و سرور پیش‌نمایش خروجی ایستا |

منشأ و تغییرات: [IMPORT.md](docs/IMPORT.md) · [گزارش این مرحله](docs/MONOREPO-OFFLINE-PROGRESS.md)

## اجرا

Node.js **۲۲٫۱۷ یا جدیدتر** (در CI نسخهٔ ۲۲)، npm و یک lockfile در ریشه:

```bash
npm ci
npm run dev          # وب؛ http://localhost:3000/law-book/
npm run dev:api      # API آزمایشی روی پورت 3001؛ مستقل از Pages
```

درگاه هنوز وصل نشده است. `GET /api/health` وضعیت `paymentsAvailable: false` دارد؛
`POST /api/payments` عمداً 503 برمی‌گرداند. `PAYMENT_MODE=live` حتی اجازهٔ شروع سرور نمی‌دهد.
تنظیمات نمونهٔ سمت سرور: `apps/api/.env.example`؛ هیچ کلید درگاهی لازم نیست و هیچ رازی وارد فرانت‌اند نمی‌شود.

## ساخت و آزمون

```bash
npm run build        # ساخت داده + Next static export + پیش‌کش SW، و تایپ‌چک API
npm run typecheck
npm test
npm run lint
npm run test:offline # Chromium واقعی؛ خروجی build لازم است
npm run preview     # سرو خروجی واقعی روی 0.0.0.0:3000
```

آزمون مرورگر روی Linux x64 از Chromium بسته‌بندی‌شدهٔ npm استفاده می‌کند؛ کتابخانه‌های همراه آن برای محیط‌های حداقلی Linux به‌صورت موقت استخراج می‌شوند (دستور `tar` لازم است). با `CHROMIUM_PATH` می‌توان مرورگر نصب‌شدهٔ دیگری معرفی کرد. اندازهٔ موبایل، شبیه‌سازی viewport است و جای تست گوشی واقعی را نمی‌گیرد. آزمون SW در حافظه برای ریشه، `/law-book` و `/Lawbook` نیز وجود دارد.

آفلاین را با **خروجی production** آزمایش کنید، نه `next dev`. ابتدا دانلود قوانین و نصب موفق SW باید تمام شوند. کش HTTP و کش درون‌حافظه‌ای Router در آزمون مرورگر مبنای موفقیت نیستند.

```bash
# استقرار در ریشهٔ دامنه به‌جای زیرمسیر
NEXT_PUBLIC_BASE_PATH= npm run build:web
# سپس همهٔ دستورهای آزمون وابسته به basePath را با همین مقدار اجرا کنید.
```

اسکریپت موجود `data:build` خروجی `public/data` و تاریخ‌های تولید را بازسازی می‌کند. snapshot دادهٔ واردشده در Git حفظ شده؛ تغییر خودکار خروجی ساخت را به‌عنوان اصلاح حقوقی محتوا منتشر نکنید. فایل خام اختیاری آراء در مخزن نیست؛ snapshot ساخته‌شدهٔ آن حفظ شده است.

## انتشار

فقط **یک** workflow انتشار Pages: `.github/workflows/deploy.yml`.
از `main` یا اجرای دستی، خروجی `apps/web/out` با basePath برابر `/law-book` منتشر می‌شود؛
ساخت، تست و آزمون آفلاین شرط انتشارند. `ci.yml` صرفاً آزمون است، نه استقرار دوم.
Pages فقط میزبان فایل ایستا است؛ API، اسرار، پرداخت و مرجع مجوز روی آن قرار نمی‌گیرند.
فعال‌سازی Pages و انتشار عمومی در این مرحله انجام نشده است. workflowهای مخزن قدیمی `Lawbook` دست‌نخورده‌اند.

## وضعیت و کارهای باقی‌مانده

- فاز ۱: [گزارش ممیزی](docs/PHASE-1-AUDIT.md) تکمیل شده است.
- آغاز فاز ۲: مونوریپو، اسکلت sandbox و اصلاح آفلاین انجام و آزمایش شده‌اند؛ **فاز ۲ کامل نیست**.
- باقی‌مانده: مدل نهایی فروش و میزبانی، دیتابیس مرکزی، حساب/OTP، سفارش و verify واقعی sandbox، مجوز امضاشده، پنل، بسته‌های امن و آزمون انتشار.
- آسیب‌پذیری‌های وابستگی‌های قدیمی هنوز رفع نشده‌اند؛ این خروجی محصول تجاری آمادهٔ انتشار نیست.

حفظ قابلیت‌ها، اعتبارسنجی پرداخت فقط سمت سرور، عدم اعتماد به LocalStorage برای مجوز، قیمت قابل‌تنظیم و حفظ نسخهٔ خریداری‌شده بدون اشتراک اجباری، اصول ثابت پروژه‌اند.
