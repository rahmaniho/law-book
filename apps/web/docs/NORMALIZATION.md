# نرمال‌سازی فارسی و معماری جست‌وجو

## چرا نرمال‌سازی؟

متن قوانین در منابع مختلف با نویسه‌های متفاوت ثبت می‌شود:

- **ی عربی (`ي` U+064A)** در برابر ی فارسی (`ی` U+06CC)
- **ک عربی (`ك` U+0643)** در برابر ک فارسی (`ک` U+06A9)
- **ة** (`U+0629`) در برخی از واژه‌ها
- **نیم‌فاصله / ZWNJ** (`U+200C`) در واژه‌هایی مانند «می‌شود»، «هفته‌ها»
- **ارقام فارسی و عربی** (`۰-۹`, `٠-٩`) در برابر ارقام لاتین
- **اعراب و تشدید** (`َ ِ ُ ّ ْ`) و نویسه‌های کنترلی RTL/LTR
- **صورت‌های نمایشی عربی (Arabic Presentation Forms)** در متن‌های OCR

اگر این نویسه‌ها یکسان‌سازی نشوند، جست‌وجوی «قانون مدنی» ممکن است ماده‌ای با
«قانون مدنى» یا «قانون‌مدنی» را پیدا نکند.

## قواعد پیاده‌شده

پیاده‌سازی مشترک در دو فایل انجام شده است:

- سمت ساخت داده: [`scripts/lib/fa.mjs`](../scripts/lib/fa.mjs)
- سمت مرورگر: [`src/lib/fa.ts`](../src/lib/fa.ts)

قواعد (تابع `normalizeForSearch`):

1. `NFKC` و حذف نویسه‌های کنترلی/جهت‌دهی و کشیده (`ـ`).
2. نگاشت `ي → ی`, `ك → ک`, `ة/ۀ → ه` و صورت‌های نمایشی عربی.
3. تبدیل **ZWNJ به فاصله** (ساده‌سازی تطبیق؛ متن اصلی دست‌نخورده می‌ماند).
4. تبدیل ارقام فارسی/عربی به لاتین.
5. حذف اعراب و تشدید، یکسان‌سازی فاصله‌های چندگانه.
6. یکسان‌سازی «أ إ آ → ا» و «ؤ → و»، «ئ → ی» در **کلید جست‌وجو** (نه در متن نمایشی).

> متن اصلی هر ماده هرگز تغییر نمی‌کند؛ فقط یک «کلید جست‌وجو» برای ایندکس ساخته می‌شود.

### پردازش درخواست

`parseQuery` درخواست را به این اجزا تبدیل می‌کند:

- `article`: شماره ماده/اصل (از «ماده ۱۰»، «ماده دهم»، «اصل ۲۲»)
- `lawHint`: نام قانون در عبارت (مثلاً «قانون مدنی» در «ماده ۱۰ قانون مدنی»)
- `terms`: واژه‌های باقی‌مانده پس از حذف ایست‌واژه‌ها

## معماری جست‌وجو

```
[ورودی کاربر] → normalizeForSearch → parseQuery
                                     │
              ┌──────────────────────┴──────────────────────┐
              │ مسیر سریع شماره ماده                         │ جست‌وجوی متنی
              │ (تطبیق دقیق شماره + نام قانون)              │ MiniSearch در Web Worker
              └──────────────────────┬──────────────────────┘
                                     ↓
                    ادغام نتایج + امتیازدهی + فیلترها
                     (دسته، سطح سند، قانون، وضعیت)
                                     ↓
                             نمایش نتایج (≤۸۰ مورد)
```

**فیلدهای ایندکس:** `textNorm`، `titleNorm` (نام قانون + فصل)، `keywordNorm`
**گزینه‌ها:** تطبیق پیشوندی برای واژه‌های فارسی، فازی‌بودن محدود، وزن بالاتر برای شماره ماده و نام قانون
**هدف کارایی:** پاسخ زیر ۳۰۰ میلی‌ثانیه برای ۶٬۶۱۸ ماده؛ ایندکس در پس‌زمینه (Worker) ساخته می‌شود و
رابط کاربری تا پایان ایندکس‌گذاری قابل استفاده است.

### نکات تخصصی

- **مسیر سریع «ماده X»**: اگر درخواست فقط شماره داشته باشد، بدون جست‌وجوی متنی از ایندکس شماره استفاده می‌شود.
- **تطبیق مواد مکرر**: مواد «مکرر» با همان شماره ولی شناسه متفاوت نگه‌داری می‌شوند.
- **کش مرورگر**: نگارش‌های داده و آدرس `/data/v<version>/…` تغییرناپذیرند؛ SW آن‌ها را برای همیشه
  کش می‌کند و در صورت انتشار نسخه جدید، فقط قوانین تغییرکرده (بر اساس هش) دریافت می‌شوند.
